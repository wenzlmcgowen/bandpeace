# bandpeace-site

**BandPeace — your band's money, in the open.** A static demo website for
bandpeace.com presenting the full (simulated) financial profile of a
**fictional** demo band, *Fly Asshole*: income by lane, monthly/yearly P&L,
simulated Schedule C tax summaries, and downloadable books.

Every number is fiction, generated by the
[band-biz-sim](/Users/edwardmcgowen/projects/band-biz-sim) Python simulator
(seed 42, 36 months starting 2026-01). The site wears a "DEMO — simulated
data" badge in header and footer.

## Layout

```
scripts/export_data.py   # runs the 36-month sim, emits site/data.json + site/files/*
site/
  index.html             # the whole site (profile, dashboard, taxes, downloads)
  style.css              # dark club aesthetic, neon magenta→cyan accent
  app.js                 # vanilla-JS dashboard (hand-rolled SVG chart, no libraries)
  data.json              # monthly income rows by bucket, expenses, Schedule C summaries
  files/                 # downloadable artifacts (xlsx, csv, simulated Schedule C txts)
```

Pure static — no build step, no frameworks, no CDN dependencies.

## Regenerate the data

Requires the sim repo and its venv at `/Users/edwardmcgowen/projects/band-biz-sim`:

```sh
/Users/edwardmcgowen/projects/band-biz-sim/.venv/bin/python scripts/export_data.py
```

The script re-runs the simulation (SimClock start 2026-01-01, months=36,
seed=42 — same wiring as `bandsim/cli.py run()`), rewrites `site/data.json`
and the per-year `site/files/schedule_c_*_SIMULATED.txt`, GENERATES
`pnl_2026.xlsx` (Fly Asshole branding, site lane names, Schedule C bridge +
quarterly set-aside arithmetic on the YTD tab) and verifies every YTD line
against data.json, copies `royalty_map_2026.csv` from the sim's `out/` dir
(it carries no band name), and prints a reconciliation: exported income
bucket totals AND per-category expense rows must match the sim's QuickHooks
ledger to the penny (yearly AND monthly), or it exits nonzero and leaves
`data.json` unwritten.

### Income buckets

| Site bucket | Source in the sim |
|---|---|
| Streaming royalties | DistroKid/Symphonic distributor statements (whole statement, incl. downloads & Content ID riding on them) |
| Publishing | ASCAP-sim, Songtrust-sim, HFA-sim statements (composition side), minus sync lines |
| Sync licensing | any statement line whose use is `sync` (Songtrust-sim composition half + Direct-to-band master half) |
| Other royalties | SoundExchange-sim + Direct-to-band non-sync (physical) |
| Live shows | `Performance - *` income entries (Venmo/Zelle gig payments) |
| Merch — online | PayPal-channel Merch Sales entries |
| Merch — in person | non-PayPal merch (none in this sim run — kept as an empty bucket with a tooltip) |
| Other income | anything else (none in this run) |

Royalty dollars are attributed to the **payout month** (cash basis), with each
collector's fee prorated across its statement lines, so buckets reconcile
exactly with the ledger's "Music Royalties" line.

## Serve locally

```sh
cd site
python3 -m http.server 8823
# → http://localhost:8823
```

(Any static server works; `data.json` is fetched, so `file://` won't.)

## Notes

- Lane chips use isolate-on-click semantics: from "All", clicking a lane
  shows only that lane; further clicks add/remove lanes; removing the last
  lane (or clicking "All") returns to every lane.
- The chart is a hand-rolled SVG stacked bar chart with a net-profit line;
  the series palette is an 8-slot colorblind-validated dark palette, distinct
  from the neon brand gradient.
- All artwork (logo, Fly Asshole cover) is original inline SVG.
- Fake EIN 00-0000000 and NOT-A-REAL-FILING notes on all tax output.
