# bandpeace-site

**BandPeace — your band's money, in the open.** The static site for
bandpeace.com: a product landing page for radical financial-transparency
profiles for bands, an **example profile** for the fictional demo band
*Fly Asshole* (income by lane, monthly/yearly P&L, simulated Schedule C tax
summaries, downloadable books), an **onboarding preview** wizard showing
how a band would connect its accounts — without ever typing a password into
BandPeace — and a **Gifts** prototype at `/gifts/` for project gifts,
supporter walls, co-signs, and receipts.

Every number is fiction, generated by the
[band-biz-sim](/Users/edwardmcgowen/projects/band-biz-sim) Python simulator
(seed 42, 36 months starting 2026-01). Every page wears a DEMO/simulated
badge in header and footer.

## Layout

```
scripts/export_data.py   # runs the 36-month sim, emits the profile's data + files
site/                    # source of truth; docs/ is its exact mirror (+ CNAME) for GitHub Pages
  index.html             # / — product landing page
  shared.css             # shared theme tokens (landing + onboard)
  landing.css
  fly-asshole/           # /fly-asshole/ — the example profile (self-contained)
    index.html style.css app.js data.json files/
  onboard/               # /onboard/ — onboarding preview wizard
    index.html onboard.css onboard.js
  gifts/                 # /gifts/ — simulated project gifts + supporter views
    index.html gifts.css gifts.js data.json
  hq/                    # /hq/ — hidden team board (link-is-the-password)
  shows/                 # /shows/ — hidden shows + logistics page (same idea)
docs/                    # deployed copy (GitHub Pages root; keep docs/CNAME)
board-backend/           # the Apps Script engine behind /hq/ AND /shows/
tests/                   # node tests/engine.test.js · node tests/shows-ui.test.js
```

Pure static — no build step, no frameworks, no CDN dependencies.
Root `/` serves the landing page (docs/index.html); the profile lives at
`/fly-asshole/`; the wizard at `/onboard/`; Gifts at `/gifts/`.

### Onboarding preview — security by design

The `/onboard/` wizard contains **no username/password/API-key fields for any
provider, on purpose**. "Connect" opens a modal explaining the real
OAuth-style flow (login happens on the provider's page; BandPeace receives a
revocable read-only token) and then merely *simulates* the connection. Band
basics typed in step 1 are stored in `localStorage` only.

## The two hidden pages

`/hq/` (the Psycho Panda team board) and `/shows/` (Wenzl's shows and their
travel / hotel / backstage logistics) are private pages on this public site.
Neither has a login: the path is boring and **the key rides in the URL
fragment** (`#pp…` / `#sh…`), which browsers never send to a server — so it
can't reach a log, and it isn't in this repo. The real gate is the engine,
which checks the key on every call and answers `{"ok":false,"error":"nope"}` to
anything else.

Both are served by **one** Apps Script deployment (`board-backend/Code.gs`) with
**two different keys and two different private spreadsheets**, so the board link
cannot open the shows and the shows link cannot open the board. One deployment
means one thing to set up and one Google "Allow" to click:
`board-backend/setup-board.command`.

No private data is in this repo — not in the pages, not in the demo data. Both
pages have a `#demo` mode that runs on obviously invented data with a DEMO
banner, which is also how they're developed and tested.

### /shows/ — how it gets written

The page is **read-only**. Wenzl sends Edward a screenshot of a booking; Edward
writes it in with the CLI in founder-os (`.claude/scripts/shows.py`), and the
page picks it up. Data shape:

| | |
|---|---|
| A **show** | title, venue, city, date (+ optional end date), status, headline, notes |
| An **entry** | belongs to one show and one tab — `travel`, `hotel` or `backstage` — and is one of six kinds: `flight`, `stay`, `ground`, `time`, `contact`, `note` |

Times are stored **exactly as the ticket writes them** (`2026-10-08T09:21`) and
are never converted: a flight time is the time the airport shows. The page
renders dates from the string rather than through a `Date` in the reader's
timezone, so the same show reads as the same day from LA, Kauai or Berlin —
there's a test that runs the formatting under five timezones to keep it that way.

## Tests

No dependencies, no runner — plain Node:

```sh
node tests/engine.test.js      # the Apps Script engine, on fake Google services
node tests/shows-ui.test.js    # the /shows/ page's pure logic
node tests/no-secrets.test.js  # nothing key-shaped got committed to this public repo
```

`tests/gas-harness.js` fakes Sheets, Properties, Lock and Utilities well enough
to run `board-backend/Code.gs` unmodified, so engine changes can be verified
before they're ever deployed. `tests/fake-engine-server.js` puts that same
engine behind a local URL, which is how the founder-os CLI and the live page get
tested end to end.

## Regenerate the data

Requires the sim repo and its venv at `/Users/edwardmcgowen/projects/band-biz-sim`:

```sh
/Users/edwardmcgowen/projects/band-biz-sim/.venv/bin/python scripts/export_data.py
```

The script re-runs the simulation (SimClock start 2026-01-01, months=36,
seed=42 — same wiring as `bandsim/cli.py run()`), rewrites
`site/fly-asshole/data.json` and the per-year
`site/fly-asshole/files/schedule_c_*_SIMULATED.txt`, GENERATES
`pnl_2026.xlsx` (Fly Asshole branding, site lane names, Schedule C bridge +
quarterly set-aside arithmetic on the YTD tab) and verifies every YTD line
against data.json, copies `royalty_map_2026.csv` from the sim's `out/` dir
(it carries no band name), and prints a reconciliation: exported income
bucket totals AND per-category expense rows must match the sim's QuickHooks
ledger to the penny (yearly AND monthly), or it exits nonzero and leaves
`data.json` unwritten.

### Income buckets

| Site bucket | Source in the sim |
|---|---|
| Streaming royalties | DistroKid/Symphonic distributor statements (whole statement, incl. downloads & Content ID riding on them) |
| Publishing | ASCAP-sim, Songtrust-sim, HFA-sim statements (composition side), minus sync lines |
| Sync licensing | any statement line whose use is `sync` (Songtrust-sim composition half + Direct-to-band master half) |
| Other royalties | SoundExchange-sim + Direct-to-band non-sync (physical) |
| Live shows | `Performance - *` income entries (Venmo/Zelle gig payments) |
| Merch — online | PayPal-channel Merch Sales entries |
| Merch — in person | non-PayPal merch (none in this sim run — kept as an empty bucket with a tooltip) |
| Other income | anything else (none in this run) |

Royalty dollars are attributed to the **payout month** (cash basis), with each
collector's fee prorated across its statement lines, so buckets reconcile
exactly with the ledger's "Music Royalties" line.

## Architecture for real

What turning this demo into the live product would take:

- **Backend with per-provider OAuth apps.** One registered OAuth (or
  token-grant) application per provider — DistroKid/Symphonic/TuneCore/CD
  Baby, Songtrust/ASCAP/BMI/SoundExchange, QuickBooks, Spotify for Artists,
  YouTube — so login always happens on the provider's page and BandPeace only
  ever holds scoped, revocable read-only tokens. Providers without public
  APIs need statement-upload or mailbox-forwarding ingestion instead.
- **Encrypted token vault.** Tokens at rest encrypted (KMS-managed keys),
  scoped per band, revocable from both sides; no credentials ever stored,
  by principle.
- **Statement-ingest jobs.** Scheduled workers pull statements on each
  provider's own calendar (monthly distributors, quarterly PROs, laggy
  mechanical societies), normalize them into the exact `data.json` shape the
  front-end already consumes (income lanes, expense categories, Schedule C
  summaries with bridge + set-aside), and reconcile to the penny — the same
  checks `scripts/export_data.py` runs today.
- **Plaid (or equivalent) for banks** and payment apps: read-only
  transactions for gig income + expenses; BandPeace never touches money
  movement.
- **Provider rate limits & sync windows.** Per-provider backoff, cached
  statements, and honest "last synced" timestamps on the profile (the demo
  already renders sync state).
- **Front-end scales as-is.** Pages are data-driven: a profile is
  `/:band-slug/index.html` + `/:band-slug/data.json` in exactly today's
  shape, so new bands are new data files (or one templated page + an API),
  not new front-end code.

## Notes

- Lane chips use isolate-on-click semantics: from "All", clicking a lane
  shows only that lane; further clicks add/remove lanes; removing the last
  lane (or clicking "All") returns to every lane.
- The chart is a hand-rolled SVG stacked bar chart with a net-profit line;
  the series palette is an 8-slot colorblind-validated dark palette, distinct
  from the neon brand gradient.
- All artwork (logo, Fly Asshole cover) is original inline SVG.
- Fake EIN 00-0000000 and NOT-A-REAL-FILING notes on all tax output.
